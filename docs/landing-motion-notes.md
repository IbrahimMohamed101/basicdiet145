التاريخ: 2026-10-07. النطاق المنفذ: **Phase 1 — Motion Foundation + Tokens** فقط.
المرجع: [LANDING_BRIEF.md](./LANDING_BRIEF.md).

## الاكتشاف وخط الأساس

- تم فحص Git ومزامنة `landing-page-research` عبر fetch ثم checkout ثم pull --ff-only. كانت الشجرة نظيفة والمزامنة دون تعارض.
- التطبيق داخل `landing-page/site`: Next.js 16.4.0، React 19.3.0، TypeScript، Tailwind 4.3.0، وApp Router. الصفحة مولدة مسبقًا كـHTML ثابت مع hydration للمكونات التفاعلية.
- مدير الحزم npm، اعتمادًا على lockfile الجذر. لا يوجد lockfile مستقل لتطبيق الصفحة؛ تم تثبيت اعتماده الحالي باستخدام `npm install --no-package-lock`، دون تغيير الإصدارات أو إضافة اعتماد. أدوات Lighthouse استُخدمت محليًا خارج اعتماد التطبيق.
- `html` يستخدم `lang="ar" dir="rtl"`. Tajawal عبر `next/font/google` بالأوزان 400/500/700 و`display: swap`. نظام الأيقونات الفعلي يعتمد على رموز نصية؛ لا توجد مكتبة أيقونات أو حركة مثبتة.
- الألوان الفعلية بعد آخر طبقة CSS: الأخضر `#108055`، hover `#0d6e49`، البرتقالي `#e95e2c`، الخلفية `#fbfaf5`، الخلفية الثانوية `#eef5e6`، النص `#14201a`، النص الثانوي `#5f6b63`، والحدود `#dfe3d8`. تم توحيد المصدر مع الحفاظ على هذه القيم.
- الحركة السابقة: انتقالات CSS مباشرة؛ مراقبان مستقلان في Header وAnalyticsTracker. `TaglineReveal` موجود لكنه غير مركب في الصفحة. لا يوجد reveal عام أو rAF مستمر حاليًا.
- خط الأساس لم يظهر overflow في المقاسات الستة. ظهر خطأ `favicon.ico` 404. في reduced-motion كان الفيديو مخفيًا دون poster. دون JS كانت أزرار CTA وفتح القائمة وفتح إجابات FAQ تحتاج JavaScript أصلًا.
- بيانات الوجبات محلية في MealGallery، والباقات في Plans، والأسئلة في `lib/faq-data.ts`. روابط التطبيق والفيديو في `lib/app-links.ts`. توجد ثلاث صور تطبيق حقيقية مستضافة لدى Apple؛ لا يوجد نقص أصول يمنع المرحلة الأولى.
- تمت مراجعة سياق Marketing OS وتعليمات المهارة الهندسية المحلية؛ هذه المرحلة تنفيذ هندسي للبنية المشتركة، ولم تغيّر الاستراتيجية أو النصوص التسويقية.

## استخدام الأساس المشترك

توقيتات الحركة: micro **200ms**، UI **320ms**، reveal **650ms**، Hero حد أقصى **1000ms**.
الإزاحة الرأسية **24px**، الخطوة **75ms**، إجمالي التأخير **600ms** كحد أقصى.
Easing للخروج `cubic-bezier(0.22, 1, 0.36, 1)`، وin-out `cubic-bezier(0.65, 0, 0.35, 1)`.
تم الإبقاء على `--ease-fluid` وتوقيتات الأقسام القديمة إلى مراحلها، لتجنب تعديل واسع غير مطلوب.

الـtokens مستخدمة بالفعل في الألوان الحالية، والحاوية، ونصف قطر الزر، وظله، وتوقيت انتقاله وz-index رابط التخطي. بقية scale مهيأة للمراحل التالية؛ لم يتم استبدال القيم في الأقسام كلها.

مثال للمراحل التالية فقط:

```tsx
import { Reveal } from "@/components/Reveal";

<Reveal index={0}>
  <article>Existing section content</article>
</Reveal>
```

`index` حسب ترتيب القراءة RTL، ولا يتم تقسيم الحروف العربية. العرض الافتراضي ظاهر؛ يبدأ keyframe فقط بعد تقاطع العنصر مع الشاشة، ثم يتم unobserve بعد أول reveal. الحركة تستعمل opacity وtranslate دون قياس أبعاد أو blur أو will-change دائم. تنظيف المكوّن يلغي اشتراكه ويعيد الحالة الظاهرة.

`observeMotionVisibility` يستخدم IntersectionObserver واحدًا لجميع مستهلكي الحركة، ويقدم الحالة الحالية للمشترك المتأخر دون انتظار تقاطع جديد؛ التنظيف آمن عند تكراره ولا يلغي اشتراكًا أحدث. يزيل الهدف عند انتهاء آخر مشترك ثم disconnect عند عدم وجود أهداف. مراقبا التنقل والتتبع يبقيان مستقلين لأن لهما حدود تقاطع ودلالات مختلفة، ولأن تغيير التتبع خارج النطاق.

`useReducedMotion` يستخدم snapshot آمنًا للـSSR بقيمة true، و`usePointerFine` بقيمة false، و`useDocumentVisible` بقيمة false. تتحقق القيم الفعلية بعد hydration عبر `useSyncExternalStore` وتستجيب للتغييرات الحية. كشف المؤشر يستخدم `(hover: hover) and (pointer: fine)`، ولا توجد listeners للمؤشر مفعلة في هذه المرحلة.

لا توجد حلقة rAF أو scroll listener جديدة. تم تأجيل `useScrollProgress` وlerp/spring حتى تحتاجها مرحلة محددة؛ لا يوجد مستهلك لهما الآن. عند إضافتهما يجب الفصل بين القراءة والكتابة، وإيقاف rAF عند الاستقرار أو الخروج من الشاشة أو إخفاء التبويب، وكتابة التقدم إلى متغير CSS بدل React state كل إطار.

## تعطيل الحركة والوسائط

- reduced-motion يعطل CSS animations/transitions والتمرير الناعم عالميًا؛ العرض فوري. لا يتم تطبيق إزاحة hover على الزر والصورة والروابط في هذا الوضع.
- `data-motion="off"` على `html` يعطل الحركة والتمرير الناعم ويوقف الفيديو ويعيد poster. إزالة السمة تعيد إدارة التشغيل حسب الرؤية والتفضيلات.
- المحتوى غير مخفي قبل JS؛ لا يوجد صنف readiness يخفي النصوص أو فترة انتظار للكشف.
- الفيديو لا يحتوي مصدر `src` في HTML؛ يوجد `data-src` فقط. لذلك دون JS أو مع reduced-motion/Save-Data منذ البداية تظهر الصورة الثابتة ولا يُطلب MP4.
- يبدأ التشغيل المرئي عبر الإدارة المشتركة فقط؛ الفيديو يحتفظ بـmuted وplaysInline وloop وpreload metadata. يتم pause خارج الشاشة وعند document.hidden، وإزالة مصدر الفيديو وإعادة poster عند تعطيل الحركة أو تفعيل Save-Data.
- رفض `play()` يعيد poster دون unhandled rejection. لا يتم تشغيل retry أو rAF مستمر.

## الفيديو والصورة الثابتة

لم يتم استبدال أو إعادة ترميز الفيديو. تم تنزيل نسخة للتدقيق المحلي ومطابقة SHA-256 مع المستند المعتمد:
`e8060486513d04a8876b7d22c30515cbce5ce41db6ebed471dcab0aee63070e3`.

الحجم **3,296,535 bytes**، المدة **8s**، الدقة **1280×720**، H.264، 24fps، وصوت AAC حسب سجل الأصل. تم التحقق من المدة والدقة فعليًا في المتصفح؛ ffprobe غير متاح محليًا، ونسخة ffmpeg الخاصة بـPlaywright لا تفك MP4. معلومات codec/fps/audio مأخوذة من `landing-page/docs/creative/hero-video-final-v1.md` بعد مطابقة بصمة الملف.

الـposter المضاف WebP، **63,248 bytes**، **1280×720**، لقطة من ثانية **7.2** في الفيديو نفسه، بجودة 85 عبر canvas المتصفح. هذه نسخة مشتقة جديدة، وليست ملف JPG المعتمد ذي البصمة المذكورة سابقًا. لا توجد صورة أو واجهة مختلقة. بصمتها:
`8506c7b75f35757f5a5ba64103f0ddbb83b7f92d6ee8ee02d0d08a6325f8613f`.

الفيديو ثقيل نسبيًا للموبايل. أي إعادة ترميز تحتاج موافقة منفصلة؛ التوصية اللاحقة: H.264 faststart، دون صوت، 24–30fps، نسخة 720p مناسبة للموبايل، وWebM اختياري. أمثلة فقط، **لم تُنفذ**:

```bash
ffmpeg -i approved-hero.mp4 -an -vf "scale=-2:720" -r 24 \
  -c:v libx264 -crf 23 -preset slow -pix_fmt yuv420p \
  -movflags +faststart hero-mobile.mp4
ffmpeg -ss 7.2 -i approved-hero.mp4 -frames:v 1 \
  -c:v libwebp -quality 85 hero-poster.webp
```

## الافتراضات والمسائل المفتوحة وNeeds data/assets

- اعتماد القيم المرئية الفعلية في آخر طبقة CSS، بدل القيم القديمة التي كانت متجاوزة.
- fallback poster من نفس الفيديو مطلوب لإصلاح reduced-motion دون بدء إعادة تصميم Hero؛ رابط الفيديو وبصمته محفوظان.
- لا نقص بيانات أو أصول يمنع هذه المرحلة، ولا microcopy أو أرقام أو ادعاءات أو روابط تجارية جديدة.
- مصدر الفيديو الخارجي والـPNG الكبيرة الحالية عوامل أداء باقية: الشعار الرئيسي 961,599 bytes؛ صور الوجبات نحو 1.02–1.30MB لكل صورة. تحسينها يحتاج النطاق المناسب في مرحلة لاحقة؛ لم تُعدّل.
- زر الإيقاف/التشغيل اليدوي للفيديو المطلوب في Hero مؤجل لمرحلة Hero، وليس منفذًا ضمن هذه المرحلة.
- دون JS: المحتوى الأساسي والصورة وروابط HTML تبقى قابلة للقراءة؛ CTA الحالي، القائمة، وفتح إجابات FAQ تبقى محدودة حسب البنية الأصلية. لا يُدَّعى اكتمال كل الوظائف دون JS.
- توجد قواعد letter-spacing عربية سابقة وتفاصيل touch/hover وCTA ثابت تحتاج مراحلها المختصة؛ لم يُجر تعديل واسع لها.
- لا اختبار قارئ شاشة أو Safari أو جهاز iOS فعلي في هذه المرحلة. الاختبارات في Chromium مع محاكاة الموبايل والتفضيلات؛ ليست إثباتًا لجميع سياسات Low Power Mode الحقيقية.
- scroll-progress وpointer parallax و3D وأي إعادة تصميم مؤجلة للموافقة الصريحة على مراحلها. بعد commit/push المرحلة الأولى، يتوقف العمل.
