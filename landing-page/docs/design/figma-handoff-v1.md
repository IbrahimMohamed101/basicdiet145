## Mobile design requirements

Mobile is designed independently, not generated by auto-stacking desktop frames.

For every section create and review a real 390px composition.

Required checks:
- headline wrapping
- CTA size and placement
- video crop
- meal image crop
- card padding
- app screenshot readability
- plan-card height
- FAQ wrapping
- footer density

### Hero mobile acceptance
At 390px:
- food video/poster reads clearly
- headline is not more than ~3–4 visual lines unless deliberately approved
- CTA is prominent
- proof line remains readable
- no horizontal clipping

At 320px:
- no overflow
- no clipped Arabic
- buttons remain >=44px tall
- cards do not collapse visually

### Responsive prototype
Prototype the 390px mobile flow from Header through Final CTA before developer handoff.

### Design parity rule
Desktop and mobile may use different compositions, but must communicate the same:
- message
- proof
- CTA priority
- visual quality

Do not accept a polished desktop with a merely functional mobile version.

## Acceptance

Figma is accepted only when desktop + mobile represent every section, the 390px and 320px QA frames pass, and no structural/copy/responsive decision is left to the developer.
