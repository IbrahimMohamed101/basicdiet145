# Basic Diet Landing Page Playbook

هذا الملف هو Skill/Playbook داخلي خاص بالمشروع، وليس Copy من Skill خارجي.

## 1. Start with the conversion

قبل أي Section يجب أن نعرف:
- من الزائر؟
- من أين جاء؟
- ماذا نريد منه أن يفعل؟
- لماذا قد يرفض؟

Primary conversion واحد، مع Secondary action عند الحاجة فقط.

## 2. Hero Rule

الـHero يجب أن يجيب خلال ثوانٍ عن:
- ما المنتج؟
- لمن؟
- ما الفائدة؟
- ما الخطوة التالية؟

نفضل Visual حقيقي للوجبات والتجربة.

## 3. Proof before claims

أي claim قوي يحتاج proof:
- Review.
- رقم موثق.
- Screenshot.
- Feature حقيقي.
- عملية واضحة.

لا نستخدم "الأفضل" أو "رقم 1" أو أرقام عملاء بدون إثبات.

## 4. Objection-driven sections

كل Section ينبغي أن يزيل اعتراضًا أو يزيد الرغبة.

أمثلة اعتراضات محتملة نحتاج التحقق منها:
- هل الطعم جيد؟
- هل السعر يستحق؟
- هل سأمل من الوجبات؟
- هل أقدر أتحكم في الاشتراك؟
- هل التوصيل مناسب؟
- ماذا لو تغير جدولي؟

## 5. Mobile first

الصفحة يجب أن تصمم للموبايل أولًا لأن CTA النهائي مرتبط بالتطبيق، ولأن جزءًا كبيرًا من traffic التسويقي سيأتي من Social Ads.

## 6. Food-first visual hierarchy

الأولوية البصرية:
1. الطعام.
2. النتيجة/القيمة للعميل.
3. سهولة الخدمة والتطبيق.
4. تفاصيل الخطة.

لا نبدأ بأيقونات عامة كثيرة قبل إظهار المنتج نفسه.

## 7. Pricing simplicity

Landing Page لا تحتاج أن تعيد بناء configurator التطبيق.

نظهر:
- plan families أو starting points.
- الفروقات المهمة.
- CTA للتخصيص الكامل داخل التطبيق.

## 8. Real app proof

Screenshots التطبيق تعتبر Proof على سهولة التجربة، لذلك يجب استخدام Screens حقيقية وحديثة بدل mockups وهمية فقط.

## 9. Performance

عند التنفيذ:
- ضغط الصور.
- responsive image sizes.
- lazy loading خارج الـHero.
- تقليل animation غير الضرورية.
- Core Web Vitals أولوية.

## 10. Measurement

لا نعتبر الصفحة "انتهت" عند النشر.

يتم قياس:
- CTA CTR.
- app-store clicks.
- WhatsApp clicks.
- bounce/engagement.
- scroll to pricing/app sections.
- conversion by traffic source.

بعد وجود بيانات، نبدأ CRO iteration بدل الاعتماد على الذوق فقط.
